# Handoff: Stennisfy — Database

## Overview

The Database page reports **historical flat-stake yield by odds band** from Stennisfy's own ATP closing-line archive. It has three tabs over the same table-and-chart layout:

| Tab | Subject | What it answers |
|---|---|---|
| **Tour** | the whole ATP archive | What did backing favourites / underdogs in each price band return, tour-wide? |
| **Tournaments** | one chosen event | Same bands for that event, each band compared to the tour baseline. |
| **Players** | one chosen player | Yield when backing (or fading) that player, split by favourite / underdog role, against the tour baseline. |

The reader is a bettor sizing an edge. Every figure is a yield on a flat 1-unit stake, every yield carries its sample size, and small samples are suppressed rather than shown.

> **Charts:** the cumulative-profit line charts have their own complete spec in
> **[CHARTS.md](./CHARTS.md)** — series colours, stroke widths, the required
> display smoothing, layer order, overlay offsets, end-plate collision rules,
> axis type and the data shape each series needs. Build the charts from that
> file; the chart notes in this README are a summary of it.

## About the design files

The files in this bundle are **design references created in HTML** — a working prototype of the intended look and behaviour, not production code to lift. The task is to **recreate this design in the target codebase's own environment** (React, Vue, Svelte, native, whatever is established) using its existing patterns, component library, and data layer.

The prototype's own component format (`.dc.html`, `<x-dc>`, `<sc-for>`, `<sc-if>`, `renderVals()`) is an authoring format for design prototypes. Do not port it. Read it as a spec: the template is the markup and styling, the script at the bottom is the data model and behaviour.

**All data in the prototype is placeholder** — the band tables are hard-coded constants (`TOUR_DATA`, `TOURN_DATA`) and every profit curve is generated by `curve()`, a seeded detrended random walk that lands on a given end value. Wire real data; keep every display rule below.

### Y-axis scaling algorithm

Plot height `H = 300` (viewBox units). Given both series' values:

1. `rawHi`, `rawLo` = max / min across **both** series (one shared scale).
2. `step` = the first of `[10, 25, 50, 100, 250, 500, 1000, 2500]` for which `(rawHi − rawLo) / step ≤ 10`, else `5000`.
3. `round = max(10, step / 10)`.
4. `hi` = `ceil(rawHi / step) * step` when the chart spends real time in profit (Tournaments with `rawHi > 0`), otherwise `max(round, ceil(rawHi / round) * round)`; `lo = floor(rawLo / round) * round`.
5. Gridlines: from `floor(hi/step)*step` down to 0 exclusive, labelled `+1,000u`; then 0 down to `lo`, labelled `0` at zero and `-2,500u` below.
6. A value maps to `y = ((hi − v) / (hi − lo)) * H`; a point index maps to `x = (x0 + (1 − x0) · i/(n−1)) * 1000`, where `x0` offsets series that start after the domain does.

Prototype curve targets (`curve(points, endValue, hump, seed)`): Tour fav `260, −891.7, 130`; Tour dog `260, −2266.4, 110`; Australian Open fav `240, +9.6, 34`; dog `240, −443.3, 40`. Seam fraction = Pinnacle matches ÷ total.

## Interactions & behaviour

- **Tab click** switches the subject and the whole content block. Filter state is *not* cleared on tab change — each tab reads only its own keys, so returning to a tab restores its selections.
- **Dropdown trigger click** toggles that menu and closes any other (`tourMenu` holds at most one key). Opening a menu clears the in-menu query.
- Tour / Tournaments menus are **multi-select** and stay open while options are toggled; Players menus are **single-select** and close on pick.
- **Search** is a case-insensitive substring match, open whenever the query is non-empty. Picking a tournament sets the subject and clears the query. The player list in the prototype is not wired to the subject — picking only clears the query.
- **Subject chip ×** sets `subjectCleared`. On Tournaments that swaps the tables and chart for the "Choose a tournament" prompt card (`background:#0a0d14; border:1px solid rgba(255,255,255,0.09); border-radius:12px; padding:22px 26px; max-width:560px`; heading 19px / 800 / `-0.01em`; body 13.5px / `line-height:1.65` / `#8b96b5` — "Search above to pick an event, and this tab will show its favourite and underdog yields by price band, the per-book split, and the cumulative profit curve across the whole archive."). The search input border turns blue until an event is picked.
- **Reset** clears all of the above.
- **Year range** selects are native; they re-scope the archive and (on Tournaments) invalidate the tour baseline column.
- No menu closes on outside click or Escape in the prototype — **add both** in the real implementation.
- **Responsive:** the window width is tracked (`< 1200px` is "narrow") only by the retired profit panel; the live layout reflows through its own `auto-fit` / `flex-wrap` rules. The band tables stack below ~1000px of content width; the control bar wraps.

## Data the real implementation needs

Per **tab subject** (tour / event / player) and per active filter set:

- Odds bands as equal-count terciles per side, each with: label, price range `[from, to]`, median price, match count, flat-stake yield.
- The same for the `All` row of each side.
- Per-book split: yield and match count for Pinnacle-priced matches and for Bet365-settled 2026 matches, per side.
- Cumulative-profit series: an ordered array of running unit profit per side (favourites, underdogs), plus the match index at which the book changes, and the season domain of the series.
- Players only: win–loss record and win %, median odds, match count and yield for each role (favourite / underdog) on both stances (backing / fading); three cumulative series per stance with their season coverage.
- Tour baselines for each band and each role, under the same filters where computable.

Yields are formatted to two decimals with an explicit sign (`+0.45%`, `-2.14%`); gaps to two decimals in percentage points (`+1.07pp`); match counts thousands-separated `en-GB`; odds to two decimals; unit values `-892u` (chart ends, rounded) or `-10.0u` (player charts, one decimal).
